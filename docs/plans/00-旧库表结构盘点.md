## 一、总览：174 张表按代际分组

| 前缀 | 数量 | 是什么 | 重写处置 |
|---|---|---|---|
| `dg_` | 71 | **老一代代购业务表**（daigou） | 过渡期共存；业务语义参考，不搬表结构 |
| `v2_` | 44 | **新一代业务表**（当前生产主表） | ★ 重写的主要参考源 |
| `deprecated_` | 21 | 废弃副本（`*_copy`、`_copy1`、`_old`） | ❌ 直接排除 |
| `admin_` | 12 | dcat-admin 后台骨架（菜单/角色/权限/日志） | 重写时用自建 RBAC 替代 |
| `sys_` | 11 | 系统表（用户/角色/菜单/字典/文件/任务/日志） | 同上，自建 |
| `relation_` | 4 | 多对多关系表 | 参考关联关系 |
| 其他 | 5 | finance 流水 / oa 通知 / 邮件任务 / 失败任务 / 设置 | 关键：`finance_order_cash_flow` |

**结论**：真正要精读的只有 **`v2_` 44 张（当前生产）+ `finance_order_cash_flow`**；`dg_` 71 张是历史业务逻辑的参考（字段语义、状态机、坑），表结构不搬。

## 三、关键表精读优先级

1. `v2_order_detail` + `v2_ecommerce_order` + `v2_ecommerce_order_item` —— 订单主链路
2. `finance_order_cash_flow` —— 财务流水（旧系统「有流水无对账」的对账原料）
3. `v2_member_webhook` + `v2_open_api_idempotency` —— 开放 API + 幂等（member 试水域）
4. `v2_platform_order_amount` —— 平台金额（**服务端重算 vs 平台回传**的对照点）

## 四、旧系统字段坑（速查，详见 docs/00 §五）
