# 01 技术栈定稿

> 状态：已定稿（2026-10-12）
> 前提：全 TypeScript 单语言，主要靠 AI 生成代码，团队负责 review 与架构把关。

## 一、核心栈

| 层       | 选型                  | 版本（基线） | 说明                         |
| -------- | --------------------- | ------------ | ---------------------------- |
| 语言     | TypeScript            | `^5.x`       | 全仓唯一语言，`strict: true` |
| 前端框架 | Next.js（App Router） | `15.x`       | SSR/SEO + 全栈能力           |
| 样式     | Tailwind CSS          | `4.x`        | 原子化样式                   |
| 组件库   | shadcn/ui             | 最新         | 基于 Radix，源码入仓可定制   |
| 运行时   | Node.js LTS           | `22.x`       | 消灭 Deno                    |
| 包管理   | pnpm                  | `9.x`        | monorepo 标准                |
| 构建编排 | Turborepo             | `2.x`        | 任务缓存 + 依赖编排          |

## 二、数据与后端

| 层       | 选型                               | 说明                                                  |
| -------- | ---------------------------------- | ----------------------------------------------------- |
| 数据库   | MySQL 8                            | 沿用现有库，过渡期与旧系统共库                        |
| ORM      | Prisma                             | 类型安全、AI 语料多、迁移一体；复杂报表用 `$queryRaw` |
| 缓存     | Redis                              | 沿用                                                  |
| 队列     | BullMQ（worker 内）                | 替代 Laravel Horizon，替代 58 个 Job                  |
| 定时任务 | BullMQ repeatable jobs + node-cron | 结算、对账、同步                                      |
| 对象存储 | 阿里云 OSS                         | 沿用                                                  |
| 消息     | 阿里云 MNS                         | 沿用（SDK 对接）                                      |
| 日志     | pino                               | 结构化日志，接阿里云 SLS                              |

## 三、前端工程

| 层         | 选型                                     | 说明                 |
| ---------- | ---------------------------------------- | -------------------- |
| 数据获取   | TanStack Query + Server Components       | 客户端态 + 服务端态  |
| 表单/校验  | react-hook-form + zod                    | AI 最熟组合          |
| 服务端校验 | zod（与 contract 包共用）                | 金额等关键字段强校验 |
| 国际化     | next-intl                                | 默认 `ja`，对日      |
| SEO        | Next.js Metadata API + sitemap + JSON-LD | 对日电商命根子       |

## 四、认证

| 端       | 方案                                            |
| -------- | ----------------------------------------------- |
| 前台会员 | Auth.js（NextAuth v5）+ JWT                     |
| 代发用户 | 同会员体系（`dfFlag` 标记）                     |
| 后台运营 | 会话 + 角色权限（RBAC，替代 dcat-admin 的权限） |

## 五、质量与测试

| 层       | 选型                                        |
| -------- | ------------------------------------------- |
| 单元测试 | Vitest                                      |
| E2E      | Playwright                                  |
| 类型检查 | `tsc --noEmit`                              |
| 代码风格 | ESLint（flat config）+ Prettier             |
| 契约测试 | contract 包共享类型 + zod，前后端编译期对齐 |

## 六、支付与外部对接

- **支付**：Stripe、PayPal（对日电商），银行转账人工核对
- **平台对接**：1688、淘宝全球购、Shopify、Rakuten、TheBase（webhook + SDK）
- **物流**：日本邮政（原 `shanjing/japanpost` 能力需自研替换）
- **通知**：钉钉 Webhook

## 七、明确排除（及原因）

| 技术          | 排除原因                                                                       |
| ------------- | ------------------------------------------------------------------------------ |
| 若依 / RuoYi  | 定制层（注解/BaseController/代码生成器）AI 语料少易幻觉；双语言；前端弱类型 JS |
| NestJS        | 比简洁不如 Next.js、比成熟不如 Java 的中间态；团队无 Java 包袱后不再需要       |
| Deno / Astro  | 冷门、招人难、原系统病根                                                       |
| Vue           | 与 React/Next 二选一，统一到 React                                             |
| Java / Spring | 全 TS 已定，不再双语言                                                         |

## 八、版本与依赖管理约定

- 所有依赖锁定在 `pnpm-lock.yaml`
- 共享依赖（react/next/tailwind/typescript/zod）在 workspace 根统一版本，用 `catalog:` 管理
- 私有包（如未来 fork 的山景能力）走 pnpm workspace 内 `packages/`
